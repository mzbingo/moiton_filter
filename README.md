# 监控视频人物筛选

Windows 本地运行，针对同一摄像头、同一人物、同一套衣服的检索。参考片段中的人物均视为目标，候选片段中任意人物匹配就保留整个视频。使用 YOLO11s 人物检测、ByteTrack 跟踪、OSNet MSMT17 人物重识别及 YOLO11s-pose 身体关键点，均为预训练模型，无需训练。

## 桌面界面（推荐）

双击项目根目录的 **人物视频筛选.exe**。当前电脑已准备好运行环境，可直接使用。

新版使用 Qt 现代桌面界面：左侧导航，圆角统计卡片，人物缩略图和状态标签，以及可拖动调整宽度的视频复核区域。

1. 点击左侧 **任务设置**，选择参考视频、待筛选、保留输出和手动排除目录，默认已填好当前项目的路径。
2. 点击 **开始筛选**，查看进度和当前处理的视频。**停止**会在安全位置保存已完成的结果。
3. 在 **已保留** 中检查结果；在 **待确认** 中检查可能漏选的视频。选中视频后可查看人物截图、点击播放并拖动进度条。
4. 在“待确认”或其他结果列表选中视频，点击 **确认保留选中** 或 **确认排除选中**，支持 Ctrl / Shift 多选。筛选完成或停止后可操作。保留会原样复制到输出目录。
5. 点击左侧 **历史与文件** 访问保留、排除、备份目录或打开历史结果；下次打开界面会载入最新结果。

**手动排除目录**默认 `manual_excluded`，可自行选择，必须与参考、输入、输出目录分开。确认排除会将原视频完整复制到该目录；如输出已有该视频，会把输出副本备份到当前报告的 `removed_from_output`。原始输入不移动、不删除。同一组参考视频再次筛选（包括“重新分析”）时，已手动排除的视频在模型处理前跳过，不再解码、检测或匹配；仍需枚举目录、读取文件元数据以识别排除项。排除目录只是存放副本，跳过依据是 `runtime/review_decisions.json` 中的复核记录。

已人工保留的视频重跑时直接原样复制，不再执行检测和匹配；如果所有候选都已有人工决定，本轮无需加载模型。改回“确认保留”会恢复到输出、取消跳过，并将排除副本归档到报告的 `restored_from_excluded`。决定按参考视频集合和源文件的路径、大小、修改时间归属；这些标识变化后使用新的记录。

GUI 默认勾选“归档旧输出”。需要自动筛选时，模型加载和参考人物校验成功后，才将已有输出视频移至 `reports/archives`；初始化或参考校验失败不会提前搬走旧结果。归档途中失败会尝试移回已搬走的文件。全部候选已排除时不归档；仅有人工保留项时，验证目录和决定后即可归档并复制。换目标时建议使用新的输出目录。

人工确认的复制、校验和保存放在后台执行，操作期间相关按钮会暂时禁用。搜索输入和批量进度更新会合并刷新列表，减少重复绘制。

“标准”使用当前衣着严格校验；“更宽松”只降低人物外观分数门槛，仍要求上下装颜色符合参考。自动筛选无法保证零漏检，建议人工查看待确认结果。

EXE 请保留在本项目目录，运行时使用现有 `.venv`、`models` 和 FFmpeg。它不是可以单独复制到另一台电脑运行的完整安装包。源代码入口为 `src/desktop_app.py`；重新打包运行 `./build_gui.ps1`。

## 命令行使用

1. 参考视频放入 `input/reference_video`；待筛选视频放入 `input/waiting_for_filter_videos`。
2. 首次运行 `./setup.ps1`，需要联网下载依赖和模型。当前环境已安装后可跳过。
3. 运行 `./run.ps1`。原始命中视频按原名复制至 `output`。
4. 查看 `reports/latest.txt` 指向的报告目录，打开 `review.html`，或使用 Excel 查看 `results.csv`。

```powershell
./run.ps1
./run.ps1 -Threshold 0.62  # 更宽松，通常会多选
./run.ps1 -Refresh        # 忽略缓存，重新提取
# 命令行需要归档旧输出时，显式指定：
./.venv/Scripts/python.exe src/filter_videos.py --archive-output
```

`run.ps1` 和直接运行 Python 默认不归档、不清理已有输出；提高阈值也不会删除以前多选的视频。GUI 的“归档旧输出”选项会向同一后台程序传入 `--archive-output`。两种入口使用相同的复核记录和匹配规则；`--refresh` 不会清除人工决定。

## 核心流程与模块

1. 校验目录，枚举视频并读取本轮人工决定；排除项提前移出处理队列，保留项标记为直接复制。
2. 存在未确认候选时，初始化模型、提取参考人物并检查可用衣着区域；没有自动筛选任务时跳过模型初始化。
3. 准备成功后按需归档旧输出，再处理候选：人工保留项直接复制，其他项经过初筛和必要的密集复查。
4. 每个完成的视频先写入结果日志，再更新界面进度；结束、正常停止或可捕获异常时导出报告。

| 模块 | 职责 |
| --- | --- |
| `desktop_app.py` / `modern_app.py` | Qt 入口、目录设置、列表复核、异步人工确认和视频预览 |
| `desktop_controller.py` / `events.py` | 启停后台进程、事件传递、运行日志和复核操作；后台结束后才解除运行状态 |
| `run_workflow.py` | 人工决定前置、参考建立、输出归档、候选调度与异常收尾 |
| `filter_videos.py` | CLI 参数、运行锁、解码采样、检测跟踪、ReID 特征和缓存接入 |
| `clothing.py` | 身体区域取色、姿态缓存，以及同一参考样本与同一轨迹的联合判定 |
| `cache_io.py` | 缓存原子写入、结构校验和可取消的 FFprobe 帧数检查 |
| `run_report.py` / `app_common.py` | 结果日志与报告恢复、文件标识、人工决定、原样复制和归档回滚 |
| `video_preview.py` | 独立 FFmpeg 预览线程、播放位置和帧队列 |

运行锁覆盖后台筛选及人工复核文件操作，避免两项任务同时改动输出。推理和界面分开运行；这轮优化保留已验证的匹配阈值，重点减少重复处理和改善中断后的可恢复性。

## 匹配规则

默认每秒约 5 帧初筛；未命中片段以约 12.5 帧/秒复查。按解码时间戳选择采样点，实际频率受原视频可用帧限制。检测在 1280 尺寸下进行，人物裁剪使用解码后的原始分辨率；人物特征包含原图与水平翻转平均。服装取色依靠肩、髋、膝、踝关键点形成的身体中心区域，减少人物框背景和随身物品的影响。

保留条件必须同时满足：ReID 相似度至少 0.72，上装颜色直方图交集至少 0.60，下装至少 0.65，且三者匹配的是同一张参考人物图；同一人物轨迹至少两帧满足条件，间隔至少 0.12 秒。衣服颜色不符不能被高 ReID 分数覆盖。评分不是身份概率，仍需要人工复核相似衣着的人物。

参考帧只保留最大人物，且人物高度需达到画面高度 30%、宽度达到 6%，用于避免目标离开后将背景小人影纳入参考；这是根据当前摄像头画面选择的参考质量规则，换摄像头需重新验证。候选人物没有这个尺寸门槛。`reference_checks.json` 记录逐段留出参考匹配的结果，只验证参考之间的一致性，不代表候选召回率。

衣服看不清、关键点不完整或只有单帧证据的疑似片段标为 `review`，保留在报告中供人工检查，不直接复制到 output。报告中的链接可打开原始输入文件。旧版“低分窄裁剪自动保留”和“颜色只能加分”的规则已移除。`reference_profile.json` 给出身体区域自动颜色统计，不做性别、款式或头发语义推断。

同名但内容不同的输出文件拒绝覆盖。`error` 需要人工检查，不应视为无人或无目标。低分或 `no_person` 也可能包含漏检，尤其远处小人、遮挡和短暂出现。

没有已标注的候选真值，因此不能报告真实召回率或保证零漏检。第一版不推断性别，文字衣着描述不是检索的硬条件；可通过参考截图核对目标衣着。换衣服请替换参考视频后新开一轮筛选。

## 报告、缓存与停止

每次运行创建独立报告，保存人物截图、出现秒数、跟踪 ID、ReID/上下装颜色相似度、支持帧数和错误。人工直接保留的条目不重复计算这些分数。

- `results.jsonl`：每个完成结果追加一行并同步落盘；运行中不反复重写整份 HTML/CSV。
- `summary.json`：周期性保存进度，结束时记录 `completed`、`cancelled` 或 `failed`；可捕获的任务异常记录 `fatal_error`。
- `results.csv` / `review.html`：任务创建时有空报告，结束或停止时生成完整导出；人工复核后更新导出。
- 异常中断后，通过 GUI 打开该报告时可从 JSONL 恢复已经完成、但尚未导出至 CSV 的行。日志最后一条未写完的记录会忽略；完整记录损坏会报错，避免静默丢失结果。

`cache` 保存人物裁剪、检测/ReID 特征和身体取色结果。缓存采用临时文件写完后替换；读取时检查数组结构及裁剪文件，损坏或不完整时重新提取。刷新前先撤销旧缓存标记，避免中断后把旧特征配上新截图。衣着缓存带姿态模型指纹，每完成一批最多 16 张裁剪就保存；完整缓存命中不重复写盘。FFprobe 帧数检查也响应停止请求。

升级后，旧版衣着缓存会在首次使用时重新计算一次；原有有效检测/ReID 缓存继续复用。因此首次重跑可能花时间更新衣着特征，不能据此承诺总耗时一定减少。

点击 **停止** 后，已完成结果和可复用缓存会保留。再次开始会重新枚举候选、读取人工决定并复用有效缓存，**不是从上次视频序号继续执行**；尚未完成的检测特征需要重新提取。选择“重新分析”会跳过旧特征缓存，但仍尊重人工保留和排除决定。

## 开发验证

在项目根目录的 PowerShell 中运行：

```powershell
# 匹配规则、缓存损坏与中断、报告恢复、人工决定和流程测试
./.venv/Scripts/python.exe -m unittest discover -s tests -v

# 真实 GPU 后台、原样复制、FFmpeg 预览和停止
./.venv/Scripts/python.exe tests/desktop_integration.py

# Qt 事件循环中的 GPU 进度、完成状态和播放/暂停
./.venv/Scripts/python.exe tests/modern_integration.py

# 临时文件上的 GUI 保留、排除、恢复、搜索和小窗口按钮布局
./.venv/Scripts/python.exe tests/desktop_review_smoke.py
```

两个 integration 脚本需要本机模型、GPU、FFmpeg 和默认输入目录，处理少量真实片段，使用 `runtime` 下独立输出且不更新 `reports/latest.txt`。GUI smoke 使用临时输入和输出。它们检查运行与交互行为，不能替代有标注数据的识别准确率评估。

2026-10-17 本机优化回归：46 项自动测试通过，实际 GPU、Qt 进度、视频播放和停止流程通过。318 个现有候选中，16 个人工排除项被跳过，其余 302 个处理完成：自动保留 31、人工保留 1、待确认 74、未匹配 176、无人 20，处理错误为 0。与原报告比较，所有非人工决定条目的状态、匹配分数、支持帧数及出现时间均一致；32 个输出副本通过 SHA-256 一致性检查。回归使用独立输出，原输出、排除副本、人工决定及最新报告指针未变。

同一批 318 条记录的本机报告写入对照：逐条重写 CSV/HTML 约 6.28 秒，追加 JSONL 后一次导出约 0.55 秒。这个数字只衡量报告写入，不代表解码或模型推理提速。验证详情保存在本机 `runtime/optimization_validation.json` 和 `runtime/report_benchmark.json`。

## 模型来源与许可

- 检测/跟踪：https://github.com/ultralytics/ultralytics （AGPL-3.0；商业集成需核对许可）
- OSNet 源码：https://github.com/KaiyangZhou/deep-person-reid ，MIT 许可见 `src/vendor/LICENSE`。
- ReID 权重：https://huggingface.co/kaiyangzhou/osnet ，使用 MSMT17 person-ReID 权重，而非仅 ImageNet 分类权重。
- GPU 环境：Python 3.14、PyTorch 2.11.0 CUDA 12.8、torchvision 0.26.0。

推理仅在本机执行，不上传视频。
